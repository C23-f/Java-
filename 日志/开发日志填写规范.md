# 项目开发日志‑填写规范
> 本文件仅存放日志书写规则，实际任务记录请查看 feishu‑shturl

## 1.日志标题格式
`## [日期 T任务号] 简短任务名称`
示例：`## [2026‑09‑02 T1 创建开发日志文档]`
- T1、T2、T3：任务编号依次递增，一个任务对应一条日志

## 2.每条日志必填字段
- **日期时间：** 开发执行日期
- **操作人：** 开发者姓名
- **模块：** 文档层 / 前端页面 / 后端接口 / 数据处理
- **做了什么修改：** 客观描述改动，分点书写
- **尝试的实现方法：** 简单说明实现思路
- **遇到的问题：** 出现的bug、卡点、疑问
- **解决方案：** 对应的处理办法
- **创新点：** 优化点，无则填写`无`
- **测试记录：** 验证结果，无测试填写`无`
- **关联提交/文件：** 本次修改涉及的文件名

## 3.GitHub网页提交要求
1. 打开`feishu‑shturl`，点击铅笔图标编辑
2. 写完日志弹出提交弹窗
   - Commit message（上方小框）：写简短中文一句话
   - Extended description（下方大框）：**留空不填**，详细内容全部写在日志文档内
3. 选择 `Commit directly to the branch main`，点击提交

## 4.格式与文件约束
1. 所有任务记录统一写在 `feishu‑log.md`，不要再新建其他日志文件
2. 新日志写在 `---` 分割线下方、所有旧日志的最上方，**时间倒序，旧日志禁止删除**
3. 文件新建时，文件名末尾必须加 `.md`；不加后缀会被识别为普通文本，无法渲染markdown格式
4. 编辑完成切换【预览】检查，不要残留多余 `**` 等格式符号

```markdown

- **模块：** 文档层

  （2）学习GitHub网页创建Markdown文件，理解`.md`后缀的作用。
- **尝试的实现方法：**
  使用Markdown格式维护开发日志，后续每次开发改动都在此文件追加记录。
- **遇到的问题：**
  GitHub网页新建文件时，如果不写`.md`后缀，就不会渲染标题列表格式。
- **解决方案：**
  创建文件时，文件名末尾手动加上`.md`。
- **创新点：**
  留存开发过程、踩坑记录，方便后续复盘回顾。
- **测试记录：**
  GitHub网页可以正常渲染本Markdown文档格式。
- **关联提交/文件：**
  `feishu‑shturl`
