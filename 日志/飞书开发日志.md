  ## [2026-09-03 T4 完成数据库设计与初始化脚本]
- **日期时间：** 2026-09-03
- **操作人：** 郭德宽
- **模块：** 数据层
- **做了什么修改：**
（1）设计全系统 9 张数据表结构，含空间字段 geography（SRID 4326）与空间索引；
（2）编写 init_db.sql 一键初始化脚本，自动建库、建表、建索引、灌测试数据、建视图与存储过程；
（3）编写可达性加权评分存储过程 sp_calc_accessibility 与缓冲区分类统计存储过程 sp_community_15min_stats；
（4）测试数据精简为 2 个小区、2 个设施（种子数据），后续补充；
（5）编写数据库设计说明文档。
- **尝试的实现方法：**
采用方案 A 共享 SQL 脚本，单文件 init_db.sql 提交 GitHub，组员本地 SSMS 执行即可获得一致数据库环境；空间数据使用 SQL Server 原生 geography 类型，STBuffer 生成米制缓冲区，STIntersects 判断相交，STDistance 计算距离。
- **遇到的问题：**
（1）显式插入 IDENTITY 主键时报"IDENTITY_INSERT 设置为 OFF"错误；
（2）数据插入与 CREATE VIEW 混在同一批次，导致"CREATE VIEW 必须是查询批次中第一个语句"；
（3）清理段漏删 v_community_score 视图，重复执行时报对象已存在。
- **解决方案：**
（1）对 region / community / facility 表在插入前后加 SET IDENTITY_INSERT ON / OFF；
（2）数据插入段末尾补 GO 分隔批次；
（3）清理段补充 IF OBJECT_ID('dbo.v_community_score','V') IS NOT NULL DROP VIEW。
- **创新点：**
评分模型中缺失设施类别按 0 分计入惩罚（而非忽略），使可达性评分更真实；分类明细以 JSON 存储，前端 ECharts 可直接消费。
- **测试记录：**
本机 SQL Server 2022 实测执行 init_db.sql，29 个批次全部成功、0 失败；1 号小区 1000 米缓冲区分析正常返回（2 个设施在圈内，覆盖 2 类，评分 6.38）；组员本机 SSMS 执行同样成功，9 张表全部创建。
- **关联提交/文件：**
`init_db.sql`
`数据库设计说明.md`
